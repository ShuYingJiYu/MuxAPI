# 路由故障恢复修复清单

本次修复针对渠道正常但本地返回 `no upstream available`、流错误误判成功及恢复状态失效。

## 行为约定

- 正常渠道优先；只有正常候选耗尽，才允许真实请求验证临时故障渠道。
- 临时故障使用 5、10、30 秒退避，与渠道熔断冷却独立。
- 恢复占用按渠道、模型控制并跨分组共享，不锁住整个分组。
- 明确的限流遵守 `Retry-After`；模型不支持默认缓存 5 分钟，再单次验证。
- 兼容旧 `0s` 设置及永久屏蔽记录，统一转换为有限缓存。
- 取消、超时、手动恢复均释放占用；迟到结果不得覆盖较新状态。
- 首次输出前解析完整 SSE 错误事件；提交响应后停止换源。
- 参数错误不影响渠道健康；认证、额度、模型不支持、限流、临时故障分别反馈。
- 监控与真实请求使用相同错误解析，不因 `[DONE]` 将错误判为成功。
- 数据库屏蔽写入与恢复按当前状态同步，防止迟到写入重新屏蔽。
- 地址、密钥、协议或代理变化时清除对应旧状态；修改名称或标签保留状态。
- 恢复占用或冷却导致不可用时，返回具体原因和重试时间；保留用户禁用及路由硬限制。
