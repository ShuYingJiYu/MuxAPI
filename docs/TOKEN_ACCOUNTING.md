# Token 计量修正方案

状态：首版已实现。调研日期：2026-10-30。

## 目标

准确记录上游报告的用量、避免重复计数，并明确独立估算的适用范围。
上游 usage 是上游的声明，不等于可独立验证的真实模型用量；本地分词也不等于最终账单。

## 1. 每次上游尝试分别计量

先完成模型映射、协议转换及请求内容调整，再对实际发送的模型和请求体计数。
发送层之后若还有影响模型输入的内容调整，也必须进入同一计数流程。
客户端请求估算继续用于发起选路；出站估算用于事后核对，两者分别保存。
保留请求模型、出站模型、响应模型（存在时）、出站协议、计量版本与基准来源。
按 request_id + attempt_no 关联出站计数和该次响应，不将失败尝试叠加到最终渠道的系数中。

## 2. 上游报告用量统一为互斥分类

完整分类时必须满足：输入总量 = 未缓存输入 + 缓存读取 + 缓存写入。

| 响应用量语义 | 输入总量 | 处理 |
| --- | --- | --- |
| 标准 OpenAI Chat / Responses / Codex | prompt_tokens 或 input_tokens | 缓存读取是其中子项，不能再加一次 |
| Anthropic Messages | input_tokens + cache_read_input_tokens + cache_creation_input_tokens | 三项分别记录，合计一次 |
| 已确认的 OpenAI 兼容缓存写入方言 | 按该方言定义的输入总量 | 若读写都是子项，未缓存量同时扣除读与写 |
| Gemini / 其他协议 | 由对应适配器解释原始字段 | 不以地址、模型名称或页面当前配置猜测字段是否重叠 |

保留原始 usage 数字和字段是否存在，区分缺失与明确的零。
字段矛盾、负数、子项超过总量时标记「用量异常」，保留证据，不截成零后当成正常用量。
图片、音频、工具和推理明细若已包含在总量中，不重复累加。
缓存是否免费只影响价格，不改变输入 Token 总量。

## 3. 流式与不完整用量

OpenAI / Responses / Codex 按协议采用最终有效的累计 usage；重复终止事件只记一次。
Claude 将起始事件与后续更新按字段是否存在合并；累计值不相加。
不跨不同快照分别取最大值，避免拼出不存在的「未缓存最大值 + 缓存最大值」。
流中断但已有明确最终用量的记录可保留该用量；只有中途用量或缺失用量时标记不完整，不计算比较系数。
保留部分用量供费用审计，不把不完整用量当成零费用。

## 4. 独立计数基准

本地估算覆盖支持格式的系统提示、消息、工具定义、调用参数与结果、输出格式，并采用近似结构开销；这仍不是服务端精确计数。
按实际出站模型选择已验证的分词器；未知模型或近似模型映射明确标记估算来源与局限。
不把整个 JSON、Base64 图片或加密推理字符串直接当成模型文本。
图片、音频、文件、服务器保存的会话历史或加密状态，只有相应计数规则/可信计数接口能够覆盖时才参与完整比较。
覆盖不全的请求显示「无法完整比较」，可保留局部估算，但不输出貌似精确的整体倍率。

可信原生计数接口用于按需验证或校准，不为每次正常转发强制增加外部网络请求。
仅使用已配置且明确获准用于计数的目标；不将请求额外发往未经配置的第三方。
同一中转的 count_tokens 与 usage 可用于检查其内部一致性，不能作为检测该中转虚报的独立证明。
计数接口存在也不自动代表结果与最终服务端上下文完全一致。
不使用被检查中转自己的 usage 将基准调整到 1，否则可能把真实异常一起消除。

## 5. 展示与统计

名称改为「输入量偏差（估算）」：比例 = 上游报告输入总量 / 可比较的出站计数基准。
同时展示两项数量、计数来源与用量完整性；分母为零、基准覆盖不足或用量异常时显示原因，不计算比例。
删除固定 1.05 / 1.20 倍的异常判定；本地估算比例作为中性信息，不据此声称渠道虚报。
日志与路由详情共用后端同一结果，不由各页面重新计算。
需要聚合时，按上游、出站模型、协议、计量版本和基准来源分别计算 sum(报告输入) / sum(基准输入)，附样本数；不平均各请求倍率。
该比例不参与费用倍率、智能路由或熔断判定。

## 6. 计费与历史兼容

Token 数量与费用独立计算：各互斥分类分别乘对应有效单价，再按明确的计费约定计算费用。
保留现有价目核对与实际扣费核对，不能用输入量偏差代替费用核对。
旧记录优先使用当次保存的协议和归一化标记，修正可确定的缓存重复。
缺少当次协议、出站基准或覆盖信息的旧记录标记历史估算/无法比较；不使用上游当前配置重写历史事实。

## 验收样例

- OpenAI 输入 1,000、缓存读取 900：未缓存 100，总输入 1,000；基准 1,000 时为 1.00 倍。
- 明确读写均为子项的兼容用量：输入 1,000、读取 600、写入 300：未缓存 100，总输入仍为 1,000。
- Claude 未缓存 100、读取 600、写入 300：总输入 1,000。
- 流式先报告总输入 1,000、后补缓存 900：最终总输入仍为 1,000。
- 工具定义变长、模型被映射或协议被转换：出站计数反映对应内容与模型变化。
- 两次上游尝试分别核对；终止事件重复、使用量缺失、字段矛盾不产生虚假的完整比例。
- 相同记录在请求页与路由详情结果一致；旧含缓存输入不再显示 1.90 倍。

实施顺序：统一用量解析与历史兼容 → 出站计数及来源记录 → 页面展示与回归验证。数据库字段变更通过新迁移实现，保留已有迁移。

## 首版实现范围

- 每次尝试记录 `token_accounting` 快照（计量版本 1），最终请求与路由记录共享最终尝试的结果。
- 已知 GPT 系列使用本地分词估算；Claude、Gemini、未知模型只保留近似数量，不计算整体比例。
- 服务器会话、加密推理、图片/文件/音频、未知输入类型与服务器工具不输出整体比例。
- 不调用新的外部计数接口；旧的上游跨模型倍率汇总不再由管理接口计算。
- 无出站基准的历史数据保留历史标记；协议只能取当次尝试快照，不用当前渠道配置补猜。
- 新增 PostgreSQL 迁移与 SQLite 模型字段；未执行生产数据库迁移或部署。

验证覆盖协议分类、异常数字、流式最终快照、字段缺失与明确零、工具估算、模型映射和跨协议重试、持久化往返及前端共享展示。
