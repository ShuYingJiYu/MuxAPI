## 行为

- 记录管理 Token 的验证结果，不记录 Token、请求正文或查询参数。
- 显式登录和后台 API 访问分开；同一分钟相同来源、接口、结果合并并保留次数。
- 失败频率按来源 IP 统计，不随浏览器标识变化重置；连续五个分钟桶合计至少十次标记频繁尝试。
- 成功来源与浏览器和近 15 天历史比较；来源变化、浏览器变化、近期失败后成功仅提示关注，不证明被入侵。
- 固定保留 15 天，每十分钟分批清理；新来源判断也只使用近 15 天记录。
- 队列有界且独立于请求计费日志。队列溢出、写入失败会在设置页提示日志可能不完整；不自动封禁 IP。
- 每分钟成功、失败各接纳最多 128 个不同来源/接口组合，已有组合继续合并；超额计入丢弃数，避免持续日志洪水占满数据库。
- 只读模式不写安全日志；未配置管理 Token 时不把访问记录为成功验证。

## 反向代理

默认仅使用 TCP 连接来源，不信任客户端可伪造的来源头。
`MUXAPI_TRUSTED_PROXIES` 可填写实际代理 IP 或 CIDR，以逗号分隔，例如 `127.0.0.1/32,::1/128`。
仅当直接连接来自配置的代理时，按从右到左的可信链解析 `X-Forwarded-For`；代理须覆盖该头或追加真实连接 IP。
不使用 `CF-Connecting-IP` 或 `X-Real-IP`。不要把所有公网地址配置为可信代理。
无效代理配置使程序拒绝启动，避免悄悄信任错误来源。连接 IP 与采用的来源 IP 同时保留。

安全日志不区分共享 Token 的实际使用者，也不是防篡改取证系统。当前仅支持查询，不提供删除接口。

- 默认展示最近 24 小时的安全事件，包括登录、验证失败和需关注的管理访问；“全部访问”包含普通成功访问与轮询。
- 列表支持完整 IP、事件类型、验证结果及 1 小时/24 小时/7 天/15 天筛选；概览仅按已查询的 IP 与时间统计，不随列表类型、结果及视图变化。
- 成功登录次数与管理访问次数分开；验证失败按访问次数累计，需关注来源按 IP 去重，记录总数为合并后的行数。
- 首次查询与刷新由服务器计算时间范围；翻页、切换视图和每页条数复用返回的时间边界，不应用未提交的筛选输入。分钟聚合仍会更新，不保证不可变快照。
- 页码、筛选和每页条数只在请求成功后生效；加载或失败保留原结果，重试重复失败的请求。每页 20/50/100 条，过期末页自动调整到实际末页。
