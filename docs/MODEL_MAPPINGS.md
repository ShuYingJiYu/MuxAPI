# 模型映射

## 页面

- 以「请求模型 → 上游实际模型」展示规则，支持名称搜索、范围/类型/状态筛选及分页。
- 详情显示创建时间、更新时间、失败计数和有效期限。
- 新增与编辑保存为长期手动规则；同一上游与请求模型已存在时，需确认覆盖。
- 编辑不能修改生效范围或请求模型；关闭新增弹窗会保留未保存草稿。
- 自动学习记录的空目标表示尚未生成映射，不计入有效映射。
- 有效映射不等于上游模型已通过可用性测试。

## 删除与历史记录

- `upstream_id=0` 是全局规则，不视为失效归属。
- 删除上游时，同一事务删除该上游的专属映射与学习失败计数，保留其他上游和全局规则。
- PostgreSQL 映射写入先取得父上游的 `FOR KEY SHARE` 锁，删除先取得 `FOR UPDATE` 锁，避免进行中的请求在删除后重新写入孤立映射。
- 列表通过服务端关联判断上游是否存在，不以浏览器是否成功加载上游列表判定失效。
- 历史残留独立显示在「失效规则」，原上游 ID 仅在详情中显示。
- `POST /admin/model-mappings/cleanup` 接收确认过的 `ids`（每次 1–1,000 个）。执行时再次核实，仅删除仍无所属上游的记录，返回实际删除数。
- 清理接口沿用管理鉴权及只读限制；新增、删除、清理和删除上游后均清除映射缓存。

```powershell
go test ./...
go vet ./...
go test -race ./internal/store ./internal/server ./internal/modelmapping -run 'TestMapping|TestService' -count=1
git diff --check
```

浏览器回归使用模拟管理接口检查筛选分页、草稿保留、模态内下拉、覆盖确认、删除失败与重试、精确清理，以及窄屏和日夜主题，不连接生产数据库。
