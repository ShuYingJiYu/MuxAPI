# MuxAPI 迭代计划

> 配合 DESIGN.md ｜ 日期：2026-06-01

## 里程碑 M1：MVP（跑通核心痛点）

目标：用户经 sub2api → MuxAPI → 多上游，验证「严格优先级 + 主动探测 + 自动回切」。

- [ ] 项目骨架：Go module、配置加载、HTTP server
- [ ] 上游抽象 `Upstream` 接口 + `relay` 类型实现（中转透传，双 header）
- [ ] 接入层：`/v1/messages` 同格式透传（先支持 Claude 一种，含 SSE 流式）
- [ ] 健康层：主动真实探测（定时发最小 token 真实请求）+ 熔断器（CLOSED/OPEN/HALF_OPEN）
- [ ] 调度层：`PriorityStrategy` 严格优先级 + 自动回切
- [ ] 转发层：反向代理 + 失败反馈健康层 + 同上游重试
- [ ] SQLite 持久化上游配置
- [ ] 端到端验证：A/B/C 三上游，杀 A 切 B，恢复 A 自动回切

**M1 验收**：核心痛点被解决，可上线最小可用。

## 里程碑 M2：管理后台

- [ ] 管理后台 API：上游增删改、优先级调整、启停
- [ ] 管理后台前端（或先用 API + 简单页面）
- [ ] 上游 api_key 加密存储

## 里程碑 M3：调度策略增强

- [ ] `ModelRouteStrategy` 模型级路由（opus 走 A 组，sonnet 走 B 组）
- [ ] `WeightStrategy` 同优先级层加权轮询
- [ ] 限流(429)降级 + 窗口过后回切

## 里程碑 M4：协议兼容扩展

- [ ] 支持 `/v1/chat/completions`、`/v1/responses`、Gemini 多格式透传
- [ ] 跨格式协议转换（复用 apicompat 链式转换思路）

## 里程碑 M5：可观测与生长

- [ ] usage/token 统计、调用日志、监控指标
- [ ] 策略链配置化（运行时调整策略顺序/开关）
- [ ] 预留更多 Strategy 扩展点（用户未来的新想法）

---

## 已确认的关键决策（2026-06-01）

1. **上游类型**：只做 `relay` 中转透传一种，不做原生官方鉴权。
2. **协议**：M1 先做 Claude `/v1/messages` 同格式透传，多格式后续迭代。
3. **健康探测**：主动真实探测（定时发最小 token 真实请求）。
4. **熔断/探测默认值**：参考 sub2api。建议连续失败 3 次熔断、冷却 30s 半开探测、探测间隔 15s（开发时再据 sub2api 实际值微调）。
5. **数据库**：SQLite 起步。
